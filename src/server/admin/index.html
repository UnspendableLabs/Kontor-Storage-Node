Reset the database

Deletes every agreement and challenge this node holds. Intended for when the Kontor signet has been reset and the node's state refers to a chain that no longer exists: the daemon then re-fetches agreements from the Portal from scratch.

Preserved: the BLS key, the daemon lock and everything else in the storage directory — only blobs named by the rows being deleted are removed, and only if you ask.

The wipe does not re-register this node, and cannot: its signer id, token and announced URL are read once at startup, and a signet reset invalidates all three. Reset with the restart ticked — the node comes back, and if the Portal no longer knows its BLS key it offers the registration above rather than exiting. Restarting also settles any download still in flight, which would otherwise write a file back after the wipe.
